# Job Hunt — Hospitality Management → Linux Systems

Nine years of management experience is not baggage to explain away — it is
the differentiator. Entry-level Linux candidates who can also run a team,
handle an angry stakeholder at 2am, and write a coherent incident report are
rare. The technical bar still has to be cleared; these files are about
clearing it AND cashing in the other nine years.

---

## Timeline (keyed to the Sept 14 exam)

| Window | Focus | Files |
|---|---|---|
| Now → Sep 14 | **Exam only.** Zero applications, zero resume polishing | none — close this folder |
| Sep 15–30 | Resume built, portfolio repo cleaned + featured, LinkedIn updated | `resume-translation.md`, `homelab-portfolio.md` |

The pre-exam rule exists because job hunting is the perfect procrastination:
it feels productive and burns exactly the hours the exam needs. One
exception: if a genuinely rare local posting appears before the exam, apply —
postings die; the rule is about not *seeking* them yet.

## Target Roles (in order of fit)

1. **Junior Linux Systems Administrator** — the bullseye
2. **NOC Technician / Engineer (I or II)** — monitoring + triage + escalation;
   night shifts common, hospitality schedule tolerance is an actual edge
3. **Technical Support Engineer (Linux products)** — heavy Linux debugging +
   customer skills; career-changer friendly, strong springboard
4. **IT Support / Sysadmin generalist at a small company** — broad exposure,
   management experience visibly valued
5. **Junior DevOps/SRE** — apply selectively; mostly wants #1's experience
   first (see career/devops-roadmap.md for the realistic path there)

Search terms beyond titles: "Linux", "RHEL", "Ubuntu Server", "entry level
infrastructure". Filter: postings mentioning specific tools you run (Ansible,
Docker/Podman, Netdata/monitoring, Git) over generic "IT support".

## Invocation

- `"Review this resume bullet: [paste]"` — expect pushback, not polish
- `"Translate this hospitality duty into ops language: [X]"`
- `"Mock interview me for a [role] position"` — technical or behavioral
- `"Review this job posting against my current skills: [paste]"` — honest
  gap read, apply/skip/apply-anyway verdict

## The One Rule

Everything claimed must survive a follow-up question. The resume says
"designed tiered zero-trust network ACLs" only because you can whiteboard it
cold. Nothing gets written that can't be defended two questions deep — the
same standard as CLAUDE.md's "if I can't explain it, it doesn't get
implemented," applied to selling yourself.
