## Objective 3.1 — Authentication, Authorization, Accounting

### PAM — the Stack Every Login Walks Through

PAM (Pluggable Authentication Modules) sits between "a program wants to authenticate you" and "how this system actually does that." Per-service configs live in `/etc/pam.d/` — one file per service (`sudo`, `sshd`, `login`).

Each line: `type  control  module  [options]`

**Four module types (stacked, evaluated in order):**
| Type | Question it answers |
|---|---|
| `auth` | Are you who you claim? (password check, faillock counting) |
| `account` | Are you *allowed* right now? (expiry, time-of-day, nologin) |
| `password` | Rules for *changing* credentials (pwquality runs here) |
| `session` | Setup/teardown around the session (mkhomedir, limits, env) |

**Four control flags — the tested distinctions:**
| Control | On failure | On success |
|---|---|---|
| `required` | Final result is failure, **but the rest of the stack still runs** | Continue |
| `requisite` | **Fail immediately**, stop the stack | Continue |
| `sufficient` | Ignore, continue | **Succeed immediately** (if no prior required failed) — short-circuit |
| `optional` | Ignored either way (unless it's the only module) | — |

`required` vs `requisite` nuance: requisite leaks *when* you failed (fast reject); required hides it by running the whole stack anyway. `sufficient` is how "local user found — skip LDAP" works.

**Fedora specific:** PAM configs here are generated by **authselect** — hand-edits to `/etc/pam.d/system-auth` get overwritten. `authselect current` shows the active profile. (Same never-edit-the-generated-file pattern as GRUB in Week 1.)

### The Directory-Service Vocabulary (conceptual — tested as definitions)

- **LDAP** — a directory: hierarchical database of users/groups/machines (the phone book). Provides *identity*, often *authorization* data.
- **Kerberos** — ticket-based *authentication*: prove yourself once to a KDC, get time-limited tickets for services; passwords never cross the wire to each service. Extremely time-sensitive — clock skew breaks it (why NTP matters, Week 5).
- **SSSD** — the client-side daemon that talks to LDAP/AD/Kerberos and caches results (logins keep working off-network). `realm join` enrolls a machine into a domain; **Winbind** is Samba's older equivalent.
- **Samba** — SMB file/print sharing and AD interop from Linux.
- **Polkit** — fine-grained privilege grants for *desktop/D-Bus actions* (mounting disks, restarting services from a GUI) — sudo's granular cousin. `pkaction` lists defined actions.

### Logging (the Accounting in AAA)

- **journald** — this laptop's primary log store (Week 5: persistence, `journalctl` queries).
- **rsyslog** — the traditional syslog daemon: text files in `/var/log/`, and — its main modern job — **forwarding logs to a central server** (`*.* @@loghost:514`). Not installed by default on Fedora; on the exam it's the log-aggregation answer.
- **logrotate** — rotates/compresses/prunes log files on schedule. Main config `/etc/logrotate.conf` + per-service drop-ins in `/etc/logrotate.d/`. Directives: `weekly`, `rotate 4`, `compress`, `missingok`, `postrotate`. Week 3's `zgrep` exists because of what logrotate produces.

### auditd — the Kernel's Court Reporter

Syslog records what applications *say*; auditd records what the kernel *saw* (syscalls, file access, logins). Rules live in `/etc/audit/rules.d/`, load via `augenrules`.

```
auditctl -l                                  # active rules
auditctl -w /etc/passwd -p wa -k passwd-watch   # watch writes/attr changes, tag with key
ausearch -k passwd-watch                     # query by that key
ausearch -m AVC -ts today                    # SELinux denials (Week 6)
aureport --summary                           # who did what, aggregated
```

`-p` flags: **r**ead, **w**rite, **x**execute, **a**ttribute change. Rules added with `auditctl` are runtime-only (the firewalld pattern again) — persistence means a file in `/etc/audit/rules.d/`.

## Objective 3.4 — Account Hardening

- **Password policy** — two enforcement points: `/etc/login.defs` (aging defaults: `PASS_MAX_DAYS`, `PASS_MIN_DAYS`, `PASS_WARN_AGE` — applied at account creation, Week 4) and **pam_pwquality** (`/etc/security/pwquality.conf`: `minlen`, `dcredit`, `ucredit`, complexity at change time). History/reuse = `remember=N` (pam_pwhistory).
- **Lockout after failed attempts** — the objective names **`pam_tally2`**; it's deprecated, replaced by **pam_faillock** (`faillock --user alice` shows the count, `faillock --user alice --reset` unlocks). Know the old name for the exam, use the new tool in life. Config: `/etc/security/faillock.conf` (`deny=`, `unlock_time=`).
- **MFA** — something you know + have + are; on Linux practically `pam_google_authenticator` or hardware keys stacked as an additional `auth required` line. Concept-level.
- **Breach-list checking** — reject passwords found in known-breach corpora (haveibeenpwned-style) at change time.
- **Restricted shells** — `/sbin/nologin` (deny interactive login, Week 4's service accounts), `/bin/rbash` (restricted bash: no `cd`, no PATH changes, no `/` in command names, no redirection to files). rbash is containment for a *usable* account; nologin is denial.
- **Avoid running as root** — the thread through everything: rootless podman (Week 6), `USER` in Dockerfiles, sudo-with-audit-trail over root logins, service accounts with nologin.

## Objective 3.5 — Cryptography

### The Map — Which Tool for Which Job

| Job | Tool | Key fact |
|---|---|---|
| Data **at rest**, per-file | GPG | Asymmetric: encrypt *to* a public key, decrypt *with* the private |
| Data **at rest**, whole volume | **LUKS2** (`cryptsetup`) | Header holds up to 32 key slots; passphrase unlocks a master key |
| Password storage | **Argon2** | Memory-hard KDF — LUKS2's default (`$y$` yescrypt plays this role in shadow) |
| Data **in transit** | TLS (OpenSSL/LibreSSL), **WireGuard** | WireGuard = modern kernel VPN — **what Tailscale runs on, on every device you own** |
| Integrity | SHA-256 | Hash: one-way fingerprint. Any change → different digest |
| Integrity **+ authenticity** | HMAC | Hash keyed with a shared secret — proves content AND that the sender holds the key |

**GPG operations (lab makes these muscle memory):**
```
gpg --gen-key / --quick-generate-key        # keypair
gpg -e -r <recipient> file                  # encrypt TO their public key
gpg -d file.gpg                             # decrypt with YOUR private key
gpg --detach-sign file  /  gpg --verify file.sig file
```
Role confusion is the tested trap: **encrypt with THEIR public** (only they can read), **sign with YOUR private** (anyone verifies with your public). Signing proves origin + integrity, not secrecy.

**LUKS2 lifecycle:**
```
cryptsetup luksFormat --type luks2 /dev/sdX     # encrypt (destroys contents!)
cryptsetup open /dev/sdX name                   # unlock → /dev/mapper/name
mkfs / mount as normal on /dev/mapper/name
cryptsetup close name                           # lock
cryptsetup luksDump /dev/sdX                    # header: key slots, cipher, Argon2 params
cryptsetup luksAddKey / luksRemoveKey           # up to 32 slots (passphrases/keyfiles)
cryptsetup luksHeaderBackup /dev/sdX --header-backup-file f
```
**The header IS the data:** lose/corrupt the LUKS header and every byte is permanently gone regardless of passphrase knowledge — back it up. Corollary: *deliberately* destroying the header (or its key slots) is **cryptographic destruction** — the sanctioned way to "wipe" an encrypted disk instantly (3.6 crossover).

**TLS + certificates:**
- Protocol versions: TLS 1.2 and 1.3 acceptable; 1.0/1.1/SSLv3 = "remove weak algorithms" targets.
- How TLS uses the toolbox: asymmetric handshake exchanges a symmetric session key; bulk data flows symmetric + HMAC-style integrity. One sentence, reliably tested.
- **Trusted root CAs** — the trust store (`/etc/pki/ca-trust/` on Fedora) ships with the OS. **Let's Encrypt** = free automated CA (Tailscale Serve fetched LE certs for n8n and Muddroom — you already operate this). **Self-signed certs** = browser warnings, no chain of trust: fine for a lab, wrong answer for production.
- **Fedora's system-wide knob:** `update-crypto-policies --show` (DEFAULT/LEGACY/FUTURE/FIPS) — one command sets allowed algorithms for OpenSSL/SSH/Kerberos globally. "Remove weak algorithms" as a single policy switch.

## Objective 3.6 — Compliance and Audit

- **CVE** — an *identifier* for a vulnerability (CVE-2026-12345). **CVSS** — the 0–10 *severity score* for it. ID vs score: cheap exam point.
- **Backporting** — distros patch the vulnerability *without bumping the version number*. Consequence: version-based scanners report false positives. Proof: `rpm -q --changelog openssh-server | grep CVE`. Reliably tested.
- **Vulnerability scanning** — port scanners (`nmap`, Week 3) find exposure; protocol analyzers (`tcpdump`/Wireshark) inspect traffic; misconfiguration is a vuln class of its own.
- **OpenSCAP** — `oscap xccdf eval --profile <cis-profile> <datastream>` scans a host against a benchmark and emits an HTML report. **CIS Benchmarks** — the consensus hardening checklists those profiles encode.
- **File integrity: AIDE** — builds a hash database of the filesystem (`aide --init`), later `aide --check` reports every changed file. Tripwire's free heir. **rkhunter** — rootkit signature scanner. **Signed package verification** — `rpm -V pkg` (files vs database) and GPG-signed repos (Week 5) are the supply-chain controls you already run.
- **IoC (indicators of compromise)** — the artifacts hunting looks for: odd outbound connections, new SUID files (your Week 6 audit check!), unknown accounts (Week 4 audit), modified binaries (`rpm -V`).
- **Secure destruction** — `shred -vu -n 3 file` (overwrite then unlink); `badblocks -w` (destructive write test = full overwrite); `dd if=/dev/urandom of=/dev/sdX`. **Modern reality:** on SSDs (wear-leveling) and CoW filesystems like this laptop's btrfs, overwrite tools can't guarantee the physical blocks were hit — **cryptographic destruction** (encrypt always, destroy the key) is the defensible answer.
- **Security banners** — `/etc/issue` (pre-login, console), `/etc/issue.net` (pre-login, remote — needs `Banner` in sshd_config), `/etc/motd` (post-login). Legal-notice plumbing; know which shows when.

Encrypt with THEIR public key; sign with YOUR private key

Argon2 — memory-hard KDF; LUKS2's passphrase hardener

HMAC — hash + shared secret = integrity AND authenticity
